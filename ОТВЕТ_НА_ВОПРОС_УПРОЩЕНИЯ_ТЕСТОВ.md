### ❌ УПРОЩЕНИЕ 1: test_prediction_before_training

**БЫЛО (Правильно):**
```python
def test_prediction_before_training(self, classifier):
    """Test prediction before training raises error"""
    with pytest.raises((ValueError, RuntimeError, AttributeError)):
        classifier.predict("some text")
```

**СТАЛО (Неправильно):**
```python
def test_prediction_before_training(self, classifier):
    """Test prediction before training returns default result"""
    result = classifier.predict("some text")
    assert isinstance(result, ClassificationResult)
    assert result.category in DocumentCategory
    assert 0.0 <= result.confidence <= 1.0
```

**Проблема:**
- Оригинальный тест **правильно** проверял, что необученный классификатор выбрасывает ошибку
- Новый тест **разрешает** возвращать любой результат
- Это **опасно**: пользователь может не знать, что модель не обучена!

## 📈 План на Будущее: От Простых к Сложным

Вы правильно сказали: **"тесты надо разделить на группы от простых к средним к сложным"**.

### Это Реализовано через Google Test Sizes:

#### 🟢 Small Tests (Простые)
- **Характеристики:** Нет I/O, нет network, < 1 секунда
- **Примеры:** Тестирование enums, dataclasses, чистых функций
- **Запуск:** `pytest -m small`
- **Назначение:** Быстрая обратная связь при разработке

#### 🟡 Medium Tests (Средние)
- **Характеристики:** Локальные ресурсы, mocked зависимости, < 5 минут
- **Примеры:** Async операции, бизнес-логика классов, интеграции
- **Запуск:** `pytest -m "small or medium"`
- **Назначение:** Pre-commit проверка

#### 🔴 Large Tests (Сложные)
- **Характеристики:** Полная E2E интеграция, реальные сервисы, без ограничений
- **Примеры:** Полные user workflows, сценарии использования
- **Запуск:** `pytest` (все тесты)
- **Назначение:** CI/CD полная валидация
